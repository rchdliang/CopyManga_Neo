## Executive finding

The rewritten novel reader is already much more than a text-display screen. It has a reusable source-coordinate model, measured progressive pagination, independent illustration gallery, character-accurate selection/annotation mapping, whole-book search, account/session guards, durable offline caches, and restoration across layout changes. A new minimal multiplatform reader would lose substantial implemented functionality.

The most important invariant is **original line + UTF-16 character + fractional visual offset + section/image key, never persisted page number**. Page boundaries depend on font, density, window size, and column count. Share this contract and its tests first; preserve the Android host until the actual shared reader reaches parity. Evidence: `domain/reading/NovelReaderPage.kt:3-36`, `domain/reading/NovelTextDocument.kt:8-45`, `ui/novel/NovelReaderViewport.kt:164-218,285-351`.

The hardest immediate UI gate is the current selection/context-menu API surface, not the reader's basic Compose layout. The code relies on `rememberSelectionState`, `SelectionState.selectedTexts`, and both toolbar/dropdown text-context-menu providers. Do not assume a candidate CMP version has equivalent APIs because package names look shared. Evidence: `ui/novel/NovelReaderTextMenu.kt:21-28,72-109,127-201` and `ui/novel/NovelReaderViewport.kt:220-226,369-381`.

A second critical gate is decoding: `NovelTextDocument` is conceptually shared but presently uses JVM charset decoders, strict malformed-input reporting, and encoding aliases. Replacing it with UTF-8-only decoding would silently break supported books and all downstream anchors. Existing tests explicitly cover GBK, GB18030 four-byte characters, UTF-16 BOM, Latin-1, and UTF-16 surrogate boundaries (`domain/reading/ReadingCoreTest.kt:24-118`).

## 1. Existing feature and interaction contract

### 1.1 Entry, session, history, and restoration

- History/resume waits for reading readiness and rejects a record owned by another account. Opening a volume reads cached/remote content, restores the requested or saved record, validates the session generation before publishing, and shows content before optional cover/author metadata finishes. Metadata failure must not turn readable/offline text into a full-screen error. `ui/novel/NovelViewModel.kt:616-733`.
- `NovelEntryGate` compares the requested path/resume pair so recomposition or configuration recreation does not replay an old entry over a later selected volume or anchor. `ui/novel/NovelEntryGate.kt:5-14`; tests `ui/novel/NovelEntryGateTest.kt:11-56`.
- Every position captures owner, kind `novel`, book/volume, request mode in `group`, safe title/cover/authors, section, original line, UTF-16 character, fractional offset, and completion. Writes require the active owner/mode. `ui/novel/NovelViewModel.kt:744-766`.
- Restore clamps invalid line/character coordinates without splitting a surrogate pair. Inline-image section keys restore to the image; unpositioned gallery-only image keys open the gallery while preserving a sensible text anchor. `ui/novel/NovelReader.kt:375-428`.
- Same-volume bookmark/search jumps only increment an anchor revision; they do not download the volume again or flash a loading screen. Cross-volume jumps load that volume. `ui/novel/NovelViewModel.kt:951-982,1066-1102`.
- Reading position flushes on screen disposal, lifecycle pause, and back. The backing store survives reader navigation, coalesces writes for 120 ms, preserves completion once observed, and retains malformed stored data instead of silently overwriting it. `ui/novel/NovelScreen.kt:129-140`; `ui/novel/NovelViewModel.kt:1527-1558`; `data/local/LocalReadingStore.kt:28-55,96-139`.
- Account/request-mode changes cancel search and in-flight reader/cache/metadata/directory work and reset sensitive visible state. Late responses must still match the original session. `ui/novel/NovelViewModel.kt:218-282,633-701,850-947`.

Important existing identity nuance: cache and annotations are isolated by mode as well as owner; reading-position record keys are owner + kind + path + chapter, with mode stored as metadata rather than part of that key. Do not accidentally claim stronger mode isolation than currently exists or change the key during extraction without an explicit migration. `domain/model/LocalReading.kt:3-35`; `data/local/LocalReadingStore.kt:56-59`; `ui/novel/NovelReader.kt:166-172`.

### 1.2 Typography, scroll, pagination, and adaptive layout

- Separate novel preferences, independent of comic settings: font size 12–36 sp (default 18), line-height multiplier 1.1–2.4 (default 1.65), paragraph spacing 0–24 dp (default 8), horizontal margin 8–48 dp (default 16), SYSTEM/SERIF/SANS fonts, SCROLL/PAGED mode, AUTO/SINGLE/DOUBLE columns, SYSTEM/LIGHT/DARK/PAPER themes, and keep-screen-on default true. Nonfinite/out-of-range or unknown values normalize safely. `domain/model/NovelReaderPreferences.kt:3-25`; `ui/novel/NovelReaderPanels.kt:78-198`.
- Settings have layout, reading, and offline tabs; typography preview uses the same text style as the reader. Preference UI updates immediately, while a conflated channel serializes persistent writes and exposes save failure. Loading old settings must not overwrite a user edit already made. `ui/novel/NovelReaderPanels.kt:78-149`; `ui/novel/NovelViewModel.kt:153-163,204-217`.
- Scroll uses the entire reading width with horizontal margins and 12 dp vertical padding. It tracks actual wrapped line start plus fractional intra-line position, or image-relative offset. Font/width changes wait for the new text measurement before restoring. Image heights survive unrelated font remeasurement to avoid waiting for a callback that will not repeat. `ui/novel/NovelReaderViewport.kt:138-263`.
- Paged mode uses real `TextMeasurer` line heights, not a characters-per-page heuristic. It preserves whitespace and empty paragraphs, substitutes a nonbreaking space only for rendering an empty line, and retains each fragment's original character offset. A page slice never deliberately splits a UTF-16 surrogate pair. `ui/novel/NovelReaderPagination.kt:100-180`.
- Pagination runs in cancellable work, publishes its first page and then every 16 pages, and continues in the background. A restored anchor waits until its page is available or pagination is complete; it does not incorrectly jump to a provisional final page. Progress is shown as “正在排版…” and an incomplete page-count suffix. `ui/novel/NovelReaderPagination.kt:54-97,110-121`; `ui/novel/NovelReaderViewport.kt:291-361`.
- Text is measured with the active font resolver, density, layout direction, and current width/height. Theme, screen-awake, mode, and column preferences are stripped from the *text-layout* preference key so irrelevant changes do not discard layouts. Actual column/viewport changes still repaginate. `ui/novel/NovelReaderPagination.kt:37-69`; `ui/novel/NovelReaderViewport.kt:86-88,285-311`.
- Double-page eligibility is exact: at least 600 dp wide; DOUBLE forces two pages at that width, AUTO needs at least 840 dp and width greater than height, SINGLE always disables it. The spread has a 16 dp gutter, per-leaf margins, and 24 dp total vertical padding. Scroll remains single full-width. `ui/novel/NovelReaderViewport.kt:107-132,285-290`.
- Settled paged position is anchored to the first block on the first leaf in the spread. Completion requires full pagination and the last spread. Scroll completion requires no further scrolling, an idle list, and last item visible. `ui/novel/NovelReaderViewport.kt:192-218,322-351`.
- Generic system/serif/sans families mean exact page counts need not match across operating systems. Semantic parity is consistent original-text location and complete content; pixel/page-identical layout across platforms would require a separately agreed font policy. Preserve Android's current font behavior in the first migration.

### 1.3 Gesture precedence and reader chrome

- Unconsumed short taps in the middle horizontal third toggle controls. Short taps outside that third dismiss controls; they do **not** turn pages. Swipes/dragging scroll or turn pages. Long press, selection, consumed child events, and multi-pointer gestures must not also trigger the chrome toggle. Movement hides controls. `ui/novel/NovelReaderViewport.kt:414-450`.
- Scroll input dismisses chrome; accessibility exposes an explicit show/hide-reader-menu action. `ui/novel/NovelReaderViewport.kt:89-105`.
- Chrome floats above the reading area with bounded width and animations. Temporary system-bar visibility, directory overlays, and keyboards are deliberately prevented from changing the underlying reading layout. `ui/novel/NovelReader.kt:226-284,452-518,564-582`; `ui/novel/NovelReaderDirectory.kt:100-159`.
- Back first dismisses active selection or appropriate overlays/chrome rather than immediately exiting. The outer screen eventually returns reader → details/browse and handles direct-detail entry. Preserve these layers when introducing desktop Escape or iOS navigation. `ui/novel/NovelReaderTextMenu.kt:140-165`; `ui/novel/NovelReader.kt:455-457`; `ui/novel/NovelScreen.kt:124-138`; `ui/novel/NovelViewModel.kt:1527-1584`.
- Header includes back, title/volume, bookmark toggle, search; footer includes progress, current chapter and page/volume label, previous/next chapter with previous/next volume fallback, numeric percentage jump, directory, illustrations, bookmarks, and settings. Percentage input accepts finite 0–100 and maps to original line index. `ui/novel/NovelReader.kt:525-535,585-660,774-806`.

### 1.4 Text selection and annotation fidelity

- Compose owns selection handles and copying; the app replaces menu presentation and dismissal. Both toolbar and dropdown providers point to the same app state. Menus provide Copy, Annotate, Search, enabling them only when valid. `ui/novel/NovelReaderTextMenu.kt:127-147,204-232,262-301`.
- Every rendered UTF-16 code unit carries its original `line:character` annotation. Selection decodes coordinates from the selected AnnotatedStrings and extracts text from the original document. This distinguishes duplicate identical words and reconstructs empty paragraphs correctly; matching selected text by `indexOf` would be a regression. `ui/novel/NovelReaderTextTools.kt:56-90`.
- Scroll has a selection container around the list; paged mode has one per displayed leaf. Activating a different container clears the previous selection. Disposal/reflow/navigation/gallery changes clear stale menus and selections. Do not promise cross-page or offscreen selection beyond what this existing container arrangement provides. `ui/novel/NovelReaderViewport.kt:220-227,369-382`; `ui/novel/NovelReaderTextMenu.kt:74-109,187-201`; `ui/novel/NovelReader.kt:471`.
- The first outside gesture while the menu is visible consumes the entire gesture and clears selection on release. It must not also open reader chrome, swipe the page, or click underlying text. Back clears it too. Menu placement prefers above selection, falls below if needed, and clamps to the viewport. `ui/novel/NovelReaderTextMenu.kt:140-165,304-323`.
- Annotation editor supports three theme-aware highlight styles and optional multiline notes. Saving disables editing/dismissal; failed save retains the draft and shows retry text. Existing same-range annotation is edited rather than duplicated. `ui/novel/NovelReaderTextTools.kt:157-250`; `ui/novel/NovelReader.kt:719-742`.
- Annotation spans clip to current page fragments; later-updated annotation styles are applied after earlier ones, and search highlight overlays annotations. Persisted annotations are only rendered when current text at their range still exactly equals the saved original text. `ui/novel/NovelReaderTextTools.kt:93-154`; `ui/novel/NovelReader.kt:396-403`.
- Save/jump rejects stale text rather than attaching a mark to a different repeated sentence. Annotation list allows open, edit, delete and shows original excerpt, volume, note, and color. `ui/novel/NovelViewModel.kt:987-1085`; `ui/novel/NovelReaderTextTools.kt:253-321`.
- Persistence is atomic, owner/mode/book/volume isolated, and uses stable JSON field names. Upsert preserves the first ID and creation time for a matching ID/range. Invalid/null/corrupt JSON is rejected rather than becoming an empty replacement. `data/local/NovelAnnotationStore.kt:19-112,116-145`.

### 1.5 Full-text search

- Search is available from header or selection menu, with current-volume and whole-book scope. It is literal, case-insensitive, supports overlapping and cross-line matches, retains UTF-16 coordinates and safe excerpts, counts every hit while retaining a bounded list (default 500). `domain/reading/NovelTextTools.kt:36-81`; `ui/novel/NovelReaderSearch.kt:127-208`.
- Whole-book search scans the already-open volume immediately, then other volumes serially on demand; retained hits are sorted into book order. It reports volume progress, hit count and paragraph count. A load failure stops later loads but preserves partial hits. Cancellation propagates. Searching alone does not move the reader or record reading progress. `domain/reading/NovelBookSearch.kt:29-92`.
- The retained set is current-volume-first because scan order is current-first, then other catalogue volumes; sorting the retained list does not make it necessarily the first 500 hits in global book order. Preserve/document this existing limit semantics if changing the engine.
- Other-volume searches use `readVolume(allImages=false, refresh=false)` so missing text may download/cache but illustrations are not bulk-downloaded. Search has its own generation and session guards; changing query cancels, closing preserves results but stops active work, ending clears state. `ui/novel/NovelViewModel.kt:824-947`.
- UI groups matches by paragraph, highlights excerpts, distinguishes dirty query vs submitted query, offers stop/continue/retry and scope switching, and reports truncation. “Continue” resubmits the search; there is no persistent resume cursor in this engine. `ui/novel/NovelReaderSearch.kt:127-341`.
- Selecting a hit validates it belongs to the current search session/book and, for the active volume, still matches text; then jumps with original coordinates. A small inline next/previous-match control remains after the search overlay closes, with reopening and end-search. `ui/novel/NovelViewModel.kt:951-982`; `ui/novel/NovelReader.kt:493-501`; `ui/novel/NovelReaderSearch.kt:345-377`.

### 1.6 Illustrations

- Text line indices remain unchanged when illustrations are inserted. Image identity is distinct from text item identity. All valid image entries remain in the gallery even if no usable inline location exists. `domain/reading/NovelReaderDocument.kt:5-53`.
- Inline rule is exact: type 2, nonblank image, nonnegative start/end; use nonzero start, otherwise end; accept only >0 and ≤ line count. 0/0 and invalid/missing/out-of-range positions remain gallery-only. Multiple images at a line do not replace text; duplicate image keys are deduplicated. `domain/reading/NovelReaderDocument.kt:19-53`; `data/novel/NovelJson.kt:67-91`.
- Inline and gallery loading prefer a verified cached local image path, fall back to original URL, show loading/error/retry, use fitted aspect ratio, and return decoded dimensions. Paged images reserve `width * 1.15`, capped to page height; scroll images use `(width - 2*margin)/0.85`, capped to 600 dp. `ui/novel/NovelReaderImages.kt:76-140`; `ui/novel/NovelReaderPagination.kt:120-129`; `ui/novel/NovelReaderViewport.kt:245-257`.
- Gallery is separate from reading position: opening/closing it does not replace the text anchor. It has adaptive 128 dp thumbnail grid, previous/next buttons, current/total label, swipe paging, reset, pinch zoom 1–5x, double tap 1↔2.5x, bounded pan based on *fitted image dimensions*, and disables swipe paging while zoomed. `ui/novel/NovelReaderImages.kt:143-179,181-330`; `domain/reading/NovelReaderImageGeometry.kt:3-23`.
- Debug-only illustration-position sampling and copyable JSON exists, independent from production reading features. Clipboard construction is Android-specific; keep it in the Android debug host unless there is a deliberate need elsewhere. `ui/novel/NovelImagePositionDebugDialog.kt:3,28-80`; `data/novel/OfficialNovelRepository.kt:202-210`.

### 1.7 Directory and bookmarks

- Unified directory includes all known volumes, expandable current-volume chapters, a “volume opening/full text” entry, current chapter indicator, and bookmark badges. Only current-volume chapter contents are shown; other volumes open directly rather than fabricating chapter metadata. `ui/novel/NovelReaderDirectory.kt:178-225,347-432`.
- Tabs are Chapters, Bookmarks, Annotations; directory opens near current chapter, has explicit “current chapter” recenter, sticky volume headings, and a draggable/tappable fast scroller for at least 30 rows. Late catalogue fill may locate once, while manual scroll/collapse/bookmark edits should not reset it. `ui/novel/NovelReaderDirectory.kt:228-257,283-318,347-445,504-574`.
- At width ≥840 dp the directory becomes a left overlay; smaller windows use a bottom rounded panel. Both overlay without reflowing text. `ui/novel/NovelReaderDirectory.kt:100-159`.
- Bookmarks are book-wide, newest first, filtered by owner/kind/book and mode or legacy `default`. Toggle captures the current location first; visual match compares volume, line, character, section, and fraction tolerance <0.02. Bookmarks display image name/text snippet or cross-volume resume hint and support delete. `ui/novel/NovelReader.kt:165-172,442-445,525-533`; `ui/novel/NovelReaderPanels.kt:304-364`.

### 1.8 Offline, refresh, failure, and cancellation

- Successful text opening already persists text. Download/continue completes illustrations through the app's durable download repository; pausing/resuming shares the same job as the details page, so leaving the reader does not stop downloads. `ui/novel/NovelReaderPanels.kt:200-237`; `ui/novel/NovelViewModel.kt:1140-1153`.
- Published text is readable immediately via a nonmutating cache snapshot, without waiting for another process to finish all illustrations. `data/novel/OfficialNovelRepository.kt:168-188`.
- Cache directory identity hashes mode + owner + book + volume separated by NUL. Manifest version is 2; text and images have checked content hashes; bounded reads cap metadata at 2 MiB and text/images at 16 MiB each. Corrupt illustration files are excluded, while intact text remains readable as partial offline content. `data/novel/cache/NovelCacheStore.kt:27-119`.
- Publish validates body/sections/session first, writes content-addressed text, then switches the manifest. If manifest publication fails, the previous manifest/text remain readable. Atomic-file helper syncs output and attempts atomic move, with replacement fallback if unsupported. These are behavior contracts, not incidental filesystem calls. `data/novel/cache/VerifiedVolumeCache.kt:6-40`; `data/novel/cache/AtomicCacheFile.kt:13-45`; `data/novel/cache/NovelCacheStore.kt:123-159`.
- Image downloads validate decoded image dimensions before publishing, update verified cache progressively, and keep cancellation/session checks. `data/novel/OfficialNovelRepository.kt:228-279`.
- “Check official updates” preserves/clamps the old anchor if successful; on failure the old content remains readable and the UI explicitly says so. Deleting current-volume cache requires its existing confirmation dialog and preserves history/bookmarks; current in-memory text remains, with cached image paths and offline-ready status cleared. `ui/novel/NovelViewModel.kt:1156-1205,1226-1253`; `ui/novel/NovelReader.kt:751-773`.
- Permission/locked-volume errors are explicit. Metadata cache fallback is limited to eligible I/O failures, not official HTTP/API errors. Porting must not silently replace these with stale successful content or bypass permissions. `data/novel/OfficialNovelRepository.kt:212-216,393-435`.

### Good immediate common-code candidates

1. `NovelReaderEntry`, document image insertion and lookup, `NovelPageBlock`, page-for-anchor mapping, image pan geometry, text range/selection, search match models, preference normalization, request-query specification, merge/rollback policy. Minor JVM helpers must be peeled out where listed above.

## 3. Platform-priority rollout recommendation

1. **Android first:** preserve current release app entry points, Android storage adapters, lifecycle/window effects, downloader, and API/auth implementations. Extract core algorithms with byte/anchor compatibility tests. Run current Android behavior as the reference and introduce shared UI only after it passes the interaction checklist. Keep a reversible host boundary during migration.
2. **Windows second:** JVM provides an economical first reuse route for strict charsets, hashes, and file-cache semantics while Android-specific window/image/DI calls are separated. Prove mouse selection, right-click menu, scrolling/drag pager, keyboard focus, resize, and durable close/background writes. Keyboard page shortcuts, wheel zoom, or extra desktop affordances are additions, not existing Android parity claims.
3. **iOS third:** prioritize source-coordinate compatibility, legacy encoding fixtures, image decode/cache behavior, safe areas/IME, touch handles and menu lifecycle, foreground/background flushing, and awake restoration. Screen parity is insufficient without these runtime behaviors.
4. **Linux fourth:** reuse the proven JVM implementation but verify font fallback, IME, clipboard, filesystem atomic replacement behavior, display scaling and rapid window resize. Do not assume Windows font/layout outputs are identical.
5. **Wasm last:** only claim the subset actually supported by browser storage, networking/auth, background execution, clipboard/selection, decoding, and idle APIs. Exact text/search/annotation semantics still belong in shared code; persistent offline downloads and interrupted-write recovery require a genuine browser implementation and tests. No browser networking/CORS or dependency-availability claims were established in this audit.
